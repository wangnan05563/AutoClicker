### 2.2 三条范式与本品定位

1. **极简点击（OP / GS / Speed）**：一屏两按钮，上手 10 秒，但无调度、无审计、停更风险高。
2. **参数面板（XClicker）**：能力与易用平衡最好，安全模式 + 随机间隔是企业/长跑场景的刚需设计。
3. **录制回放（KeymouseGo / AHK）**：能力上限最高，但脚本概念重，普通用户流失。

**本品定位建议**：不做第 3 类（录制回放仅作 P2 的轻量补充），而是把「**长时无人值守的可靠性 + 企业部署可控性**」做成护城河——竞品在这一点上集体空白：

- KeymouseGo 明确有速度上限、不记录轨迹；XClicker 仅 X11；GS 停更近十年；OP 无托盘无防锁屏。
- 本品的防锁屏/保持会话、单实例、托盘、麒麟适配，恰是「挂机签到 / 远程值守 / 长时间在线」场景的核心价值，当前**能力有、体验与可控性不足**（见 §4）。

| # | 现象 | 证据（行号） | 影响 |

## 5. 优化需求池（33 条）

优先级口径：**P0** = 缺陷/可用性阻断，先修；**P1** = 对齐竞品基线，决定竞争力；**P2** = 差异化与工程化，可排后。
工作量为人天估算（含自测），仅作排期参考。

### A. 客户体验提升（CX）

## 7. 技术选型建议

| 议题 | 建议 | 理由 |
|---|---|---|
| UI 框架 | **短期留在 tkinter/ttk + 自建 Style 体系**；若 P1 后仍需复杂布局/动画，再评估 PySide6 | 迁移成本约 5–8 人天且打包体积 +60 MB；本品界面复杂度尚在 ttk 可控范围（侧边栏 + 4 页） |
| 主题实现 | ttk `Style` + 主题字典，不引入第三方主题库 | 依赖少、单文件打包友好；`ttkbootstrap` 体积与兼容性风险高于收益 |
| 计时 | `time.perf_counter` 单调时钟 + 补偿式 sleep | `time.sleep` 累积漂移在毫秒级不可接受 |
| 输入注入 | Windows `SendInput`（比 `mouse_event` 更规范）；Linux X11 用 XTest、Wayland 用 ydotool | `mouse_event` 已废弃标记；Wayland 必须走 uinput 层 |
| 线程模型 | 单工作线程 + 事件队列 + 可中断的 `Event.wait(timeout)` | 替代 `time.sleep(1)` 轮询，停止响应从「最多 1 s」降到毫秒级 |
| 配置 | 单 JSON + `schema_version` + Profile 目录 | 兼容现有 `~/.auto_clicker_config_py3.json` |

## 8. 非目标（明确不做）

1. **反检测 / 绕过反作弊**：不提供随机化以规避检测的营销承诺，不做驱动级隐藏。随机间隔仅用于拟人节奏，文档需注明「多人游戏使用可能违反服务条款」。
2. **进程注入 / 内存修改**：超出工具定位，且带来杀软误报与合规风险。
3. **无提示的后台点击**：默认托盘可见、状态可查；不做静默服务化（企业审计不可接受）。
4. **全功能脚本引擎**：录制回放仅做「点击+按键+延时」最小集，不与 KeymouseGo/AHK 正面竞争。
