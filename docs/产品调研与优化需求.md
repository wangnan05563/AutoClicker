# AutoClicker 产品调研与优化需求

> 版本：v1.0　调研日期：2026-11-10　对应任务：T05201
> 调研对象：GitHub / Gitee / 官网可公开访问的同款自动点击类工具，结合本项目源码实际能力做差距分析。

结论：本项目在「长时间低频点击 + 防锁屏」这一细分场景是清晰的（间隔可到 1 小时），但在**安全可控**（急停、次数上限）、**节奏真实度**（毫秒/抖动）、**可复用**（配置方案、热键自定义）、**观感**（主题、图标）四个维度均落后于同款产品。

## 4. 差距与机会

### 4.1 客户体验（CX）

1. **不可控的启动是最痛的体验问题**：点击开始后只能靠记忆中的 F6 停止，且 F6 同时是启动键，误触即开始、再误触才停；竞品普遍提供独立急停 + 启动倒计时 + 鼠标位移 failsafe。
2. **"测试点击"名不副实**（F-1），用户点击后看不到任何真实反馈，直接损害信任。
3. **长时间运行缺乏终点**（F-2）：这是本项目主打"1 小时间隔挂机"场景的硬伤，用户需要"点 N 次后自动停"或"跑 N 小时后停"。
4. 关闭窗口即退出（F-9），与"托盘常驻挂机"的产品定位冲突。
5. 日志不可回看（F-6），出问题无法定位，也无法证明"确实点过"。

### 4.2 功能扩展（FN）

1. 只支持左键单击，覆盖不了右键菜单、中键、双击、需要按住才生效的目标。
2. 只有整秒节奏，无法满足毫秒级连点或"拟人化"低频点击。
3. 只有单一区域/中心点，缺少多点位序列与"手动输入坐标"这类精确控制入口。
4. 无配置方案，换场景要重新录入所有参数。
5. 开机自启在 README 中被承诺但未实现（F-11）。

### 4.3 UI 升级（UI）

1. 信息架构扁平：核心控制、参数、状态、日志四块视觉权重接近，缺少"一眼看到能否点、点了多少次、还有多久"的主次关系。
2. emoji 充当图标（🖱️ ⚡ 📊）在不同 Windows 版本渲染不一致，且与"工具型软件"的观感不符。
3. 布局存在硬伤：固定 `width=680` 的 Canvas 窗口 + 矛盾的 minsize（F-10），高 DPI 或字体放大后会挤压。
4. 日志区无折叠、无分级、无过滤，长跑后滚动区域成为噪音。
5. 状态反馈只有红/绿圆点与文字，缺少倒计时进度这样的"时间可视化"。

### 4.4 主题升级（TH）

1. 无主题概念，颜色散落在控件构造参数里（F-8），改一次配色要动几十处。
2. 无深色模式；挂机场景常在夜间使用，亮白窗口刺眼。
3. 无品牌化视觉资产（现有 social-preview 仅为仓库封面），控件层级、圆角、间距不统一。

## 6. 技术方案建议

1. **主题层选 ttkbootstrap**：纯 Python、与 Tkinter 同源、支持运行时 `theme_use()` 与浅/深色成对主题，改造成本远低于迁移到 Qt/customtkinter；单文件 PyInstaller 打包方式可保留（[build_exe.py](file:///d:/code/otherProjects/AutoClicker/scripts/build_exe.py) 只需新增 hidden-import）。
2. **调度改用单调时钟**：以 `time.monotonic()` 计算下一次点击时刻，替代逐秒 `sleep(1)` 倒计时，才能支持毫秒间隔且不随系统休眠漂移。
3. **安全三层**：独立急停热键 → 鼠标位移 failsafe（可关）→ 次数/时长硬上限，任一触发都走同一个 `stop_clicking(reason)` 入口，保证状态一致。
4. **配置升级为带版本号的 Schema**：`config_version` + `profiles[]`，加载时按版本迁移旧 `~/.auto_clicker_config_py3.json`，避免用户配置丢失。
5. **日志用标准 `logging` + `RotatingFileHandler`**，UI 侧挂一个 Handler 转发到文本框，天然获得分级与滚动。
6. **渐进拆分**：当前单文件可先按 `core/`（点击调度、平台适配、配置）、`ui/`（界面与主题）拆包；拆分与主题改造分开提交，保证每次改动可独立验证与回滚。

- M1（P0 止血）：CX-01/02/03/05/06 —— 安全可控 + 修复名不副实的功能 + 文档对齐。
- M2（P1 能力补齐）：FN-01/02、CX-07/08/09/10/11/12、FN-03/04。

## 8. 风险与不做项

- **不做**通用键鼠录制回放（KeymouseGo 已覆盖且与"低频挂机"定位不符），除非后续明确需要。
- **不做**图像识别/模板匹配点击（引入 OpenCV 依赖，与轻量单文件目标冲突）。
- 热键在 Linux 下依赖 X11 与权限，Wayland 环境需降级说明；failsafe 与游戏反作弊的兼容性需在 README 中提示。
- 主题改造会触碰大量控件构造代码，必须与业务逻辑改动分提交，降低回归风险。
