# AutoClicker 崩溃诊断：PyInstaller 临时目录清理失败

## 现象

用户反馈软件运行一段时间后崩溃，并弹出：

```
Warning
Failed to remove temporary directory: C:\PYFIX~4\_MEI000033a42
```

## 结论

该弹窗**不是崩溃发生点**，而是 PyInstaller `--onefile` 在进程退出时清理 `_MEIxxxxx` 临时解包目录失败。真正导致进程退出的原因需要看 `~/.auto_clicker_logs/crash.log`；旧版本没有安装崩溃钩子，所以原现场已丢失。

## 诊断证据（2026-11-22）

1. `~/.auto_clicker_logs/autoclicker.log` 最后一条是 2026-11-21 23:20:29 的正常“仅移动到位置”，之后没有异常、没有退出记录。
2. Windows Application/System 事件日志在 23:15–23:35 无 Error/Critical。
3. `C:\pyfix_tmp` 下残留多个 `_MEI0000xxxxx` 目录，时间跨越 11-18 至 11-22。
4. 多个 `AutoClicker.exe` 进程的 `MainWindowTitle` 为 `Warning`，符合 PyInstaller 父进程卡在清理失败弹窗的特征。

## 根因判断

- 旧构建是 `--onefile`，每次启动把 1000+ 个文件解包到 `%TEMP%\_MEIxxxxx`。
- 退出时若 Python 解释器/后台线程/全局钩子/杀软仍持有临时目录内 DLL 的句柄，父进程删除目录就会失败并弹窗。
- 旧代码退出时只等待点击线程 0.2 秒，然后 `root.destroy()`，没有强制终止解释器；`keyboard.unhook_all()` 也可能在异常钩子状态下阻塞。

## 本次修复

1. 退出路径 `_shutdown_runtime` 现在会：
   - 先置 `is_running=False`；
   - 停止运行时 tick 与防锁屏线程；
   - 唤醒 `_wait_exact` 并等待点击线程 1.5 秒；
   - 托盘/系统唤醒状态清理；
   - `keyboard.unhook_all()` 放到 daemon 线程，最多等 0.5 秒，避免卡死。
2. `exit_application` 在清理完成后执行 `root.quit()` + `root.destroy()`，并刷盘。
3. Windows 主入口在 `mainloop()` 返回后调用 `os._exit(0)`，让进程立即释放所有 DLL/临时目录句柄，避免 PyInstaller 父进程清理失败。
4. 新增独立崩溃诊断 `~/.auto_clicker_logs/crash.log`：
   - `faulthandler` 捕获致命信号；
   - `sys.excepthook` 捕获主线程未处理异常；
   - `threading.excepthook` 捕获后台线程异常；
   - Tk `report_callback_exception` 捕获 UI 回调异常；
   - 记录 APP_START/APP_EXIT 生命周期。
5. 重新构建：`20261122-002`，32.19 MB。

## 验证

- 隔离用户目录启动新 exe 后关闭：无 Warning 弹窗，`crash.log` 记录 `APP_EXIT: cleanup finished` 与 `mainloop returned, exit_code=0`。
- 人为触发未捕获异常：`crash.log` 正确记录 traceback。
- 已用新 exe 替换 `F:\Program Files\AutoClicker\AutoClicker.exe`，旧文件备份为 `AutoClicker.exe.bak-20261122`。

## 遗留问题

- `--onefile` 在本机首次解包约 34 秒（32 MB、1000+ 文件，受杀软扫描影响），远超 PRD 的冷启动目标。彻底解决应切到 `--onedir`（PRD 已建议 onedir 优先）；本次只修复退出清理与崩溃可观测性，未改打包形态。
- 若用户再次遇到“运行一段时间后退出”，请提供 `~/.auto_clicker_logs/crash.log`，其中会记录真实异常栈、线程名与 Tk 回调栈。
