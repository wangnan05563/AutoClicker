## 0. 结论先行

1. **市场已经分成三层产品**：极简连点（MouseClickTool、oriash93）、参数面板（Blur、AlphaClicker、本品）、录制自动化套件（KeymouseGo、CrossMacro、Pulover）；另有一层生态底座（AutoHotkey/PyAutoGUI）。本品的能力骨架已经越过第一层，处在第二层的中上位置，但体验封装明显落后。
2. **真正的差距不再是“能不能点”**，而是四件事：首启与异常时的引导、录制/宏能力、信息架构与视觉完成度、主题系统的可扩展性。
3. **最强护城河仍是“长时无人值守”**：防锁屏保活、每日定时与跨零点/休眠补算、单实例、托盘、审计日志、离线安装与麒麟适配。竞品在这组能力上几乎集体空白。
4. **主题升级是投入产出比最高的品牌刷新**：AlphaClicker 用「5 套内置主题 + 用户主题目录 + 模板文件」把一个小工具做出了辨识度，值得直接借鉴。
5. **不要追 CrossMacro 的全功能平台**。建议先做「看得见的体验升级」（P0，约 23 人天），再把「录制回放 MVP」做成差异化补充（P1），图像/OCR、MCP、全功能脚本引擎单独立项评审。

一句话建议：**把 AutoClicker 从“参数齐全的工具”升级为“跑得久、停得下、看得懂、换得了皮肤”的值守产品。**

## 2. 市场地图与竞品拆解

### 2.1 四类产品，四种打法

| 类型 | 代表 | 核心卖点 | 目标用户 | 对本品的意义 |
|---|---|---|---|---|
| 极简连点 | MouseClickTool、oriash93 | 打开即用、体积小、参数少 | 一次性、轻量需求 | 守住「10 秒上手」的底线，不能为了高级功能把首屏做重 |
| 参数面板 | Blur、AlphaClicker、本品 | 毫秒间隔、随机节奏、按键/次数/坐标 | 挂机、签到、固定按钮 | 本品主战场；差距在交互与外观，不在参数数量 |
| 录制自动化 | KeymouseGo、CrossMacro、Pulover | 录制→编辑→回放、调度、触发、CLI | 重复流程、测试、批量操作 | 功能扩展方向；先做最小集，不做脚本平台 |
| 生态底座 | AutoHotkey、PyAutoGUI | 脚本语言 / 库 | 开发者、深度定制 | 不作为竞品正面竞争，可作为能力参照 |

### 2.2 五个标杆各自做对了什么

**Blur Auto Clicker：把“性能”做成可感知的承诺。**
- 口号直接写「an auto clicker that actually clicks at the speed you set」，把高 CPS 精度变成卖点。
- Simple / Advanced 双模式：简单模式只留开关、按键、热键；高级模式再加占空比、随机 CPS、边缘停止、次数/时长上限、双击、指定坐标。
- 支持按住或切换启动、键盘按键、按秒/分/时/天设置节奏。
- 可借鉴：**双模式 + 性能可验证**；不照搬：Tauri/WebView2 带来的约 100MB 内存占用，对麒麟离线环境不友好。

**KeymouseGo：把“录制”做成低门槛脚本。**
- 录制鼠标点击与键盘输入，保存为可读的 JSON5 脚本，可手工编辑、循环、条件、子程序。
- F6 启动、F9 停止，执行次数 0 表示无限；支持插件、主题 XML、语言切换、命令行运行。
- 明确不记录鼠标轨迹，官方承认速度有上限——边界诚实，反而降低支持成本。
- 可借鉴：**录制结果必须是可编辑文本，而不是黑盒二进制**；不照搬：完整脚本语义与插件体系，维护成本过高。

**CrossMacro：把“连点器”做成自动化工作台。**
- 录制鼠标移动、点击、滚轮、键盘，可分离录制；支持播放速度、倒计时、重复次数、暂停/继续。
- 可视化编辑：增删排序、文本、延时、剪贴板、窗口动作，进一步支持变量、循环、条件。
- 支持等待颜色/图像/窗口出现，按窗口类名/标题/进程名或工作区触发，配置档案隔离。
- 提供 CLI 与本地 MCP，GUI、命令行、Agent 共用同一引擎；跨 Windows/Linux/macOS，上架 Microsoft Store / Flathub。
- 可借鉴：**录制→编辑→调度→触发→CLI 的完整闭环**；不照搬：一次做全，导致概念密度高、普通用户学习曲线陡。

**AlphaClicker：把“主题”做成差异化。**
- 现代 UI，固定/随机间隔、鼠标键、单击/双击、无限/指定次数、当前位置/指定坐标、置顶、热键。
- 1.4 分支提供 5 套内置主题（Light / Dark / Nature / Earth / Glass）+ `User Themes` 用户目录 + `BaseThemeTemplate.xaml`，只改 HEX 色值即可新增主题。
- 还支持按住点击、设置持久化、置顶与主题独立保存；按进程限定点击仍在开发中。
- 可借鉴：**内置主题 + 用户主题模板 + 实时预览**，这是低成本、高感知的升级；不照搬：XAML 主题绑定 Windows/WPF，Tkinter 需改用 JSON 令牌。

**MouseClickTool：把“小”做到极致。**
- 20KB 主程序、在线版仅 5KB，中文界面，主打「简单好用、体积小巧、性能好」。
- 可借鉴：**便携与低资源仍是独立卖点**；不照搬：功能过窄，无法承接值守/调度场景。

### 2.3 六条市场趋势

1. **从“连点”走向“自动化”**：录制、宏库、调度、触发、CLI 正在成为分水岭；KeymouseGo 10.6k 星、CrossMacro 持续活跃，说明需求真实存在。
2. **性能开始被明码标价**：Blur 把「设定 50 CPS 就真的 50 CPS」写成首页文案，高 CPS 精度成为新的信任状。
3. **外观成为低成本差异化**：AlphaClicker 仅 331 星，却靠主题系统形成辨识度；用户愿意为“好看”买单。
4. **双模式成为标准解法**：Simple / Advanced 同时服务新手的「马上能用」和老手的「参数自由」，比堆设置页更有效。
5. **分发与集成平台化**：CrossMacro 上架 Microsoft Store / Flathub，并提供 CLI/MCP；KeymouseGo 跨三平台。单机 exe 仍有市场，但“可被脚本/Agent 调用”是新趋势。
6. **极简仍有生存空间**：MouseClickTool 1.5k 星证明「小、快、免安装」永远有人要；产品不必把所有功能塞进主界面。

### 2.4 本品的位置（文字版象限）

| | 工具型外观 | 精致 / 品牌化 |
|---|---|---|
| **基础点击** | MouseClickTool、oriash93 | Blur、AlphaClicker |
| **自动化套件** | AutoHotkey、Pulover | CrossMacro、KeymouseGo |
| **长时值守** | **AutoClicker 当前** | **AutoClicker 目标位置** |

本品的独特生态位是第三行：**长时值守 + 企业部署 + 国产化桌面**。竞品要么偏个人娱乐，要么偏开发者脚本，没有人把「防锁屏 + 定时 + 审计 + 离线安装」做成一套。

## 4. 差距诊断

### 4.1 已经对齐的基线（不要重复造）

毫秒/秒间隔与 jitter、左/右/中键与双击/长按、次数/时长上限、多点位序列、每日定时启停与跨零点/休眠补算、配置档案导入导出、开机自启、前台窗口校验、可自定义热键、托盘与单实例、防锁屏独立保活、运行日志与统计导出、浅/深/跟随系统主题、高 DPI、Wayland ydotool 后端、NSIS 安装包与一键发布。

这些能力说明产品骨架不弱，问题在于**没有把它们组织成一条顺滑的用户旅程**。

### 4.2 五个结构性差距

| # | 差距 | 证据 | 用户可感知表现 |
|---|---|---|---|
| 1 | 首启与异常引导不足 | 首启有推荐安全预设与弹窗引导，但无 3 步向导、无场景选择；无安全模式确认；无诊断中心 | 新用户不知道先设什么；Wayland/热键冲突/自启失败时只看到一句报错 |
| 2 | 自动化深度不足 | 无录制回放、宏库、条件等待、CLI；PRD FR-D02/D03 仍是 P2 未实现 | 重复流程只能手配参数，无法“做一遍再回放” |
| 3 | UI 信息架构未落地 | PRD FR-K01 要求左侧导航 + 固定操作条，但当前仍是 720×800 单页长滚动，多张卡片堆叠 | 首屏认知过载；高级功能与常用功能混在一起；1024×768 需滚动 |
| 4 | 主题系统仍是“两套配色” | `theme.py` 只有 light/dark 两套字典；无高对比、无用户主题、无强调色、无字体回退 | 看起来像“能用的工具”，不像“有品牌的产品”；麒麟缺字时观感差 |
| 5 | 交付与增长链路缺失 | 无 About 页、无单一版本源、无自动更新、无多语言；README 末段仍称 ydotool 未接入 | 版本口径不一致；升级靠手动下载；海外/非中文用户无法使用 |

### 4.3 护城河（必须加厚，不要稀释）

- **会话保持**：防锁屏保活独立于点击运行，周期断言 + 1px 微抖动，可对抗策略型锁屏；竞品矩阵中唯一 ✅。
- **长时调度**：每日启停、跨零点、休眠唤醒补算，适合夜间值守。
- **企业可控**：单实例、档案、目标窗口校验、日志落盘、离线安装、NSIS 静默部署。
- **国产化桌面**：银河麒麟 + X11/Wayland 降级指引，是竞品完全不覆盖的市场。
- **中文支持与本地社区**：中文文档、中文界面、国内下载链路。

### 4.4 明确不值得追的能力

| 能力 | 不追的理由 |
|---|---|
| 全功能脚本引擎（AHK/Pulover 级） | 语义、调试、兼容、支持成本极高；与“轻量值守工具”定位冲突 |
| 插件市场 | 供应链与安全风险；企业内网无法审核第三方插件 |
| 驱动级隐藏 / 反检测 | 合规与杀软风险，PRD 已明确不做 |
| macOS 原生支持 | 目标用户不在 macOS；CrossMacro 已占住跨平台心智 |
| 多机集中管理控制台 | 属于企业版另一条产品线，当前版本不承载 |
| 图像/OCR 识别点击 | PRD §4 明确 out of scope；准确率、性能、支持成本都高，最多做 P2 评审项 |

## 5. 优化需求池（40 条）

优先级口径：
- **P0**：本轮必须做，影响首次体验、品牌感知或“承诺了没做到”的一致性。
- **P1**：对齐竞品基线，决定竞争力。

## 7. 技术落地方案

### 7.1 UI 框架选择

| 方案 | 迁移成本 | 优点 | 风险 | 结论 |
|---|---|---|---|---|
| **ttk + 自建令牌主题** | 0 | 体积小、打包稳、可控性最高、与现有 3.4k 行代码兼容 | 圆角/动画能力弱，需要 Canvas 模拟 | **V2.3 首选** |
| ttkbootstrap | 0.5–1 人天 | 30+ 现成主题、Bootstrap 风格 | 主题偏通用、依赖增加、与手工 Style 可能冲突 | 仅作可选加速，不做硬依赖 |
| CustomTkinter | 8–12 人天 | 现代圆角、深色开箱即用、13.6k 星 | 自定义控件生态弱、托盘/菜单需另接、包体增大 | V3.0 若视觉仍不达标再评估 |
| PySide6 | 15+ 人天 | 最强布局/动画/图表能力 | 包体 +60MB、LGPL 合规、重写成本高 | 不建议当前阶段 |

**建议**：V2.3 不换框架，先把 `theme.py` 升级为「令牌 + 主题包 + 校验器」，把 `ui.py` 升级为「导航壳 + 页面 + 组件」；用扁平卡片、细分隔线、8px 网格做出精致感，不追求圆角与复杂动画。

```json
}
```

校验规则：必填 14 个颜色令牌；正文/背景对比度 ≥4.5:1，控件边界 ≥3:1；只允许 JSON 数据，不允许脚本、URL、文件路径；非法包拒绝加载并给出字段级错误。

### 7.3 录制宏 schema（示例）

```json
{
  "schema": "autoclicker.macro/1",
  "name": "每日签到",
  "speed": 1.0,
  "loop": 1,
  "steps": [
    {"t": "move", "x": 120, "y": 340, "delay_ms": 300},
    {"t": "click", "button": "left", "count": 2, "interval_ms": 80},
    {"t": "key", "key": "ENTER", "delay_ms": 200},
    {"t": "wait", "ms": 1500}
  ]
}
```

约束：不记录鼠标轨迹；不支持任意代码；步骤类型仅 `move / click / key / wait`；播放前校验坐标在虚拟桌面范围内；Esc/F8 可在任意步骤中断。

### 7.4 代码落点

| 模块 | 改动 |
|---|---|
| `auto_clicker_layers/theme.py` | 主题令牌、主题包加载、对比度校验、系统主题检测 |
| `auto_clicker_layers/ui.py` | 导航壳、页面容器、简单/高级模式、组件样式 |
| `auto_clicker_py3.py` | 向导、诊断中心、关于页、托盘增强、暂停/继续、热键录制 |
| 新增 `auto_clicker_layers/recorder.py` | 录制/回放引擎、宏 JSON 读写、步骤校验 |
| 新增 `auto_clicker_layers/diagnostics.py` | 环境采集、日志尾部、脱敏、诊断包导出 |
| 新增 `auto_clicker_layers/i18n.py` | 语言字典、运行时切换、日期/数字格式 |
| `scripts/build_exe.py` | 版本注入、延迟导入、安装包资源、可选签名 |
| `docs/` | 主题模板、宏格式说明、发布说明、迁移指南 |

### 7.5 非功能约束

- **线程**：录制钩子、回放线程不得直接操作 Tk；统一 `queue.Queue` + 主线程 `after` 消费。
- **性能**：主题切换 <1s；页面切换 <100ms；冷启动 <3s；8h 内存增长 ≤5MB。
- **安全**：主题包/宏文件只读数据，不执行代码；自动更新必须 SHA256 + 签名；MCP 默认关闭且仅回环。
- **可访问性**：正文对比度 ≥4.5:1；焦点环 2px；全流程键盘可达；尊重「减少动效」。
- **兼容**：Windows 10/11、麒麟 V10 X11；Wayland 保留 ydotool 路径与明确降级提示。

## 9. 验收与度量

| 指标 | 当前基线 | 目标 | 验证方式 |
|---|---|---|---|
| 首次成功运行耗时 | 未测（仅推荐安全预设） | <60s | 5 人可用性测试，录屏计时 |
| 主流程布局 | 720×800 单页滚动 | 1024×768 无滚动 | 四档 DPI 截图走查 |
| 主题切换耗时 | 188–422ms（浅→深） | <1s，5 套主题均达标 | 自动化计时 + 截图 |
| 主题对比度 | 仅浅/深，未逐项实测 | 正文 ≥4.5:1，边界 ≥3:1 | 对比度工具逐令牌检测 |
| 录制回放 | 不支持 | 10 动作 100% 原序 | 自动化脚本 + 人工抽检 |
| 高 CPS 偏差 | 不支持区间 CPS | 50 CPS 偏差 <5% | 1000 次时间戳统计 |
| 冷启动 | 源码 5.3–5.7s；onedir 约 4.2s | <3s | 目标机 10 次冷启动取中位数 |
| 8h 稳定性 | 已有浸泡报告，需复测 | 无崩溃、内存 ≤60MB | 8h 浸泡 + 日志扫描 |
| 错误诊断覆盖 | 分散提示 | 5 类常见错误均有指引 | 故障注入测试 |
| 文档一致性 | README 有过时口径 | 0 处过时口径 | 发布前文档检查清单 |

> 不做默认埋点。采用本地统计、人工可用性测试、GitHub Release 下载量与 Issue 数量作为代理指标，避免隐私与合规争议。

## 10. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| UI 重构引入回归 | 高 | R1 期间冻结功能改动；四档 DPI 截图回归；主流程自动化冒烟 |
| 录制钩子触发杀软误报 | 高 | 代码签名；首次使用说明；不做隐藏/注入；提供白名单指引 |
| 主题包被写入恶意内容 | 中 | 仅 JSON 数据；schema 校验；禁止 URL/路径/脚本；加载前预览 |
| Scope creep 到全功能脚本 | 高 | 录制 MVP 明确四类步骤；新步骤类型需评审 |
| Linux 主题检测碎片化 | 中 | gsettings/KDE 双路径；检测失败回退手动选择 |
| 多语言改造波及全部 UI | 中 | 等 UI 信息架构冻结后再做；先抽离文案字典，再切换 |
| 自动更新被劫持 | 高 | HTTPS + SHA256 + 代码签名；失败回滚；可关闭 |
| 1 人排期过长 | 中 | P0 先交付；P1 可拆给第二人；P2 单独立项 |
