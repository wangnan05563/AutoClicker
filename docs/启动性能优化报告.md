# 启动性能优化报告（T05267 / REQ-005）

- 日期：2026-11-16
- 环境：Windows 10 Pro 19045，Python 3.14.3，PyInstaller 6.20.0
- 基线：T05277 源码冷启动 5316.1 / 5719.8 / 5430.1ms；onedir 3969.7 / 4675.1 / 4181.1ms
- 结论：**本轮将首屏可见时间降到最好 2204.7ms、常规 3079.5ms；但当前系统持续 100% CPU 负载下三连测不稳定，NFR-05 3s 门槛尚未稳定成立。T05267 标 `done`，不标 `verified`。**

## 1. 本轮优化点

文件：`D:\code\otherProjects\AutoClicker\auto_clicker_py3.py`

1. **日志初始化后移**：`setup_logging()` 从 `__init__` 同步调用改为 `root.after(250, ...)`；`logging.handlers`（会拉入 shutil/socket/pickle）不再阻塞首屏。此前日志先进入 `_pending_logs`，初始化后补写。
2. **PIL 图标后移**：启动/停止/测试按钮不再在 `setup_ui` 内绘制图标，改为 `root.after(250, _load_action_icons)`；主题切换仍按需重绘。
3. **热键/托盘后移**：`keyboard` 全局钩子导入约 1.3s，注册从 50ms 推迟到 300ms；托盘从 120ms 推迟到 450ms，窗口先可见。
4. **惰性导入**：
   - `logging`/`RotatingFileHandler` → `setup_logging` 内导入；
   - `subprocess` → Linux/macOS/打开日志目录分支内导入；
   - `filedialog`/`simpledialog` → 导出/导入/保存方案时导入；
   - `shutil` → Wayland 检测与配置备份时导入。
5. **随机源降级但保持安全**：`secrets.SystemRandom` → `random.SystemRandom`（仍基于 `os.urandom` 的系统安全随机源），避免启动期拉入 `secrets` 的 hashlib/hmac 链。

## 2. 首屏可见时间（真实窗口，no-after-timers 探针）

探针：`C:\pyfix_tmp\ac_startup_visible_probe.py`；结果：`C:\pyfix_tmp\ac_startup_visible_report.json`

| 次数 | 总耗时 | import | init |
|---|---:|---:|---:|
| 1（系统刚被 Defender 扫描） | 9055.5ms | 2595.8ms | 6459.7ms |
| 2 | **2204.7ms（低于 3s）** | 724.4ms | 1480.3ms |
| 3 | 3079.5ms | 1202.3ms | 1877.2ms |

- 最佳 2204.7ms，较 T05277 源码基线 5316.1ms 下降约 58%。
- 常规 3079.5ms，距 3s 仅差约 80ms；但当前系统 `Win32_Processor.LoadPercentage` 持续 100%，测量方差大，不能据此宣称稳定达标。
- 原 `ac_startup_probe.py` 的 `root.update()` 会执行 250/300/450ms 延迟任务，把日志/热键/托盘时间算进启动，已不适合评价本次「首屏可见」优化；本轮改用只做 `update_idletasks()` 的可见窗口探针，并保留两组数据说明口径差异。

## 5. 结论与剩余

- 本轮是有效优化：import 从约 1.7–3.0s 降到 0.7–1.2s；首屏最好 2.2s，常规 3.08s。
- 3s 门槛仍未稳定通过：当前主机 100% CPU（Defender/Chrome/Doubao 等持续占用），且 Tk 创建 + UI 搭建仍约 1.5–1.9s。
- 后续若要稳定达标，需要：① 将「高级配置/日志」面板也改为窗口后按需构建；② 在空闲真机复测；③ 评估 onedir/onefile 打包策略（T05250/T05277 已记录 onefile 解压开销）。
- 因此 T05267 只标 `done`，不标 `verified`，不把 2204.7ms 单次结果当作验收通过。
