# 响应延迟打点报告（REQ-004）

- 项目：AutoClicker
- 日期：2026-11-16
- 环境：Windows / DESKTOP-G10O4NL / `.venv` Python
- 探针：`C:\pyfix_tmp\ac_response_probe.py`
- 原始数据：`C:\pyfix_tmp\ac_response_report.json`
- 方法：真实 Tk 主窗口，100ms 间隔运行中，分别通过停止按钮、`emergency_stop()`（F8/Esc 同一入口）、failsafe 触发停止，用 `perf_counter` 记录从触发到 `is_running=False` 且按钮复位的耗时。

## 结果

| 通道 | 触发方式 | 响应耗时 | 判定（<200ms） |
|---|---|---|---|
| 停止按钮 | `stop_btn.invoke()` | 62.709 ms | 通过 |
| 急停 | `emergency_stop()` | 60.163 ms | 通过 |
| failsafe | 光标移至左上角 | 101.642 ms | 通过 |

- 停止后状态文案均为「已停止」，停止按钮均复位为 disabled。
- 日志存在「自动点击已停止」打点记录。

## 判定

三通道响应均低于 PRD FR-E01 的 200ms 阈值，实测通过。注：按钮/急停为同进程真实 Tk 调用；F8/Esc 全局热键未向系统注入按键，避免同时触发用户正在运行的 AutoClicker 实例，热键回调最终走同一 `emergency_stop()` 入口。
