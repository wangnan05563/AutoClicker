# AutoClicker 视觉规范约束与 UI 框架评估

> 对应 PRD §1.1 / T05274：限定 ttk 可实现范围，评估 PySide6 迁移条件。本文是技术评估与约束文件，不改变现有 UI。

## 1. 结论先行

- **V2.x 继续使用 Tkinter/ttk**，不做 PySide6 迁移。
- 视觉规范限定在 ttk + Canvas 可实现的范围：纯色背景、卡片、边框、字体、间距、悬停/禁用态、简单进度条；不做复杂圆角、阴影、模糊、透明度动画、嵌入 3D/视频。
- 迁移 PySide6 的触发条件见第 6 节；未触发前不投入迁移。

## 2. 当前 UI 资产盘点

| 层级 | 实现 | 说明 |
|---|---|---|
| 根窗口 | `tk.Tk` | 单一主窗口，标题固定 `WINDOW_TITLE` |
| 常规控件 | `ttk` | Button/Label/Entry/Combobox/Checkbutton/Notebook/Frame/LabelFrame/Progressbar/Treeview |
| 原生绘制 | `tk.Canvas` | 区域选择遮罩、日志/提示条背景、简易图形 |
| 文本 | `tk.Text` | 日志输出（只读场景） |
| 弹窗 | `tkinter.messagebox` / `simpledialog` | 字段级错误已改为行内红字；操作级用顶部横幅；致命级才用模态 |
| 托盘 | `pystray` + Pillow | 浅色/深色双套图标 |

## 3. ttk 允许范围（硬约束）

### 3.1 允许

- 主题：`clam` 作为深色/浅色统一基底；禁止在深色主题下使用 `vista` 导致输入框白底。
- 颜色：通过 `ttk.Style` 的 `configure/ map` 设置背景、前景、边框、选中态；颜色值集中定义，禁止散落硬编码。
- 字体：`微软雅黑`/系统无衬线字体，基准 9pt；DPI 缩放由 `setup_dpi_awareness()` 统一处理，不在单个控件二次放大。
- 间距：8px 栅格（4/8/12/16），卡片内边距 8~12，控件间距 6~8。
- 状态：`normal/disabled/active/focus` 四态必须有可见差异；禁用态对比度不低于 3:1。
- 圆角/边框：仅使用 ttk 主题原生边框或 1px 实线；不伪造阴影。
- 图标：16/32px PNG/ICO，浅色/深色各一套；托盘图标必须双套，避免任务栏看不清。

### 3.2 不允许（需走变更评审）

- 复杂圆角卡片、投影、毛玻璃、渐变背景、透明度动画。
- 自定义标题栏、无边框窗口、异形窗口。
- 嵌入式视频/3D/WebView。
- 依赖第三方 ttk 主题包（除非通过依赖评审并锁定版本）。
- 为视觉效果引入 Qt/Electron 等第二套 UI 运行时。

### 3.3 例外

区域选择遮罩使用 `tk.Toplevel + Canvas` 全屏半透明绘制，属于交互必需，不作为常规视觉样式复用；其坐标/DPI 逻辑必须保持现有 `setup_dpi_awareness()` 前置约束。

## 4. 视觉验收清单

- [ ] 100%/125%/150%/200% 缩放下无裁切、无重叠、无文字截断。
- [ ] 浅色/深色主题下，卡片、输入框、下拉框、按钮、日志区颜色一致，无白底残留。
- [ ] 字段错误为行内红字，不弹模态；操作错误为顶部可关闭横幅；致命错误才模态 + 日志。
- [ ] 禁用态、悬停态、焦点态可区分；键盘 Tab 顺序可用。
- [ ] 托盘图标在浅色/深色任务栏均可见。
- [ ] 不新增非 ttk 控件，除非在本文第 3.3 节登记。

## 5. PySide6 迁移评估

### 5.1 潜在收益

- 更好的高 DPI、主题、圆角/阴影/动画支持；
- 更强的表格/树/停靠面板控件；
- 无障碍与键盘导航更完整；
- 跨平台视觉一致性更好。

### 5.2 成本与风险

| 维度 | 评估 |
|---|---|
| 包体 | PySide6 运行时通常增加数十 MB，PyInstaller 单文件启动可能超过 NFR-05 的 3 秒门槛 |
| 兼容 | 银河麒麟/arm64 需要验证 PySide6 wheel 与系统 Qt 库；Wayland 下仍需输入后端降级 |
| 许可 | PySide6 为 LGPL，需遵守动态链接/分发义务；商业分发需法务确认 |
| 改造量 | 现有 UI 约千行级，迁移需重写布局、主题、托盘、区域选择遮罩与 DPI 逻辑 |
| 回归 | 全部 GUI 冒烟、热键、托盘、主题、DPI、区域选择需重跑；短期稳定性风险高 |
| 维护 | 双运行时并存会增加打包/文档/问题排查成本 |

### 5.3 决策

**V2.x 不迁移。** 现有 ttk 已满足 P0/P1 的视觉与交互要求；迁移收益主要是视觉上限，不解决当前核心稳定性问题。将预算优先投入安全、长稳、平台适配。

## 6. 迁移触发条件（满足任一才启动评估）

1. 产品明确要求复杂动效/圆角/阴影/嵌入图表，且 ttk 无法在可接受工作量内实现；
2. 企业客户/无障碍规范强制要求 Qt 级控件能力；
3. 现有 ttk 在目标平台出现无法修复的 DPI/主题缺陷；
4. 包体预算与启动时间预算重新放宽，且完成 2 周技术 spike。

### 6.1 启动迁移前必须完成

- 2 周 spike：主窗口 + 深色主题 + 区域选择遮罩 + 托盘 + 打包，测启动时间/包体/内存；
- 麒麟 x86/arm64 真机冒烟；
- LGPL 合规评审；
- 全量 GUI 回归与回滚方案。

未完成上述前置，不进入迁移排期。

## 7. 落地约束

- 新增控件优先使用 `ttk`；确需 `tk.Canvas/tk.Text` 时在代码注释标注用途与主题适配方式。
- 颜色/字体/间距集中管理，禁止新增散落样式常量。
- 主题切换必须同时覆盖 ttk 与 Canvas/Text；禁止只改根窗口背景。
- 视觉变更须附 100%/150%/200% 截图与深色/浅色截图，纳入人工复验记录。
