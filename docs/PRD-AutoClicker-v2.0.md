## 0. 评审结论摘要

**结论：有条件通过。**

本次评审把 v3 调研的 40 条需求逐条对照了当前代码、旧 PRD、V2.1/V2.2 回归报告、启动性能与视觉评估文档，结论如下：

1. **产品定位不变，但表达要升级**：继续做「长时值守 + 企业可控 + 国产化桌面」，同时补齐「好看、好上手」两块短板。
2. **P0 范围锁定 11 条、约 23 人天**：只做体验、UI 骨架、主题底座，不掺入录制、图像、CLI、自动更新等新引擎能力。
3. **录制/CLI 不构成需求变更**：PRD 旧版 FR-D03 / FR-D02 已定义，本次只是把录制从 P2 提升为 P1 MVP；仍禁止扩展为全功能脚本引擎。
4. **P2 进入门禁**：图像/颜色触发、MCP/Agent、自动更新必须分别通过需求变更、安全、发布工程评审，未通过不排期。
5. **技术路线不换框架**：R1/R2 继续 ttk + 自建主题令牌；CustomTkinter / PySide6 只在 R2 后视觉仍不达标时评估。
6. **两个历史遗留问题先修正口径**：配置文件名不再改名；版本号拆成 `APP_VERSION` + `BUILD_ID` 双轨，避免旧 PRD 的“单版本源”与构建号冲突。

**评审条件**：
- P0 范围不得插入 P1/P2 需求；UI 重构期间冻结功能改动。
- 录制 MVP 只允许 `move / click / key / wait` 四类步骤，不做脚本语义、插件、轨迹录制。
- 主题包只允许 JSON 数据，不允许脚本、URL、文件路径。
- 图像/颜色等待、MCP、自动更新三项未通过评审前，不得进入开发；OCR 识别不纳入本期。
- 发布门禁必须包含 8h 浸泡、四档 DPI、5 套主题对比度、1024×768 无滚动。

## 1. 背景与问题定义

### 1.1 产品现状

AutoClicker 当前版本 2.0.2，主程序约 3.4k 行，已拆出 `config / engine / theme / platform_io / ui` 五层，具备：

- 毫秒/秒间隔、jitter、左/右/中键、双击/长按、次数/时长上限、多点位序列、鼠标跟随/只移动；
- 每日定时启停、跨零点、休眠补算；配置档案、导入导出、开机自启、单实例；
- F6 启停、F8/Esc 急停、failsafe、前台窗口校验；
- 防锁屏独立保活、托盘、日志、统计导出、浅/深/跟随系统主题、高 DPI；
- Wayland ydotool 后端、PyInstaller 单文件、NSIS 安装包、GitHub Release 发布链路。

结论：**参数能力不弱，体验封装不足。** 当前更像“功能齐全的工具”，还不是“有品牌感、可长期值守的产品”。

### 1.2 竞品结论（摘要）

市场分三层：极简连点、参数面板、录制自动化套件。KeymouseGo（10,660★）证明录制需求，Blur（2,122★）证明性能与双模式，CrossMacro（474★）证明录制→编辑→调度→触发的闭环，AlphaClicker（331★）证明主题系统能形成差异化。

本品在参数面板层已接近 Blur，且多出多坐标、定时、防锁屏、档案；真正差距是首启引导、录制/宏、UI 信息架构、主题系统。完整矩阵见 v3 调研文档。

### 1.3 用户痛点

| # | 痛点 | 现状证据 | 用户可感知表现 |
|---|---|---|---|
| P1 | 首启路径不清晰 | 有推荐安全预设与弹窗引导，但无 3 步向导、无场景选择 | 新用户不知道先设间隔还是先取点 |
| P2 | 异常处理弱 | 错误主要写日志，无统一诊断面板 | Wayland、热键冲突、自启失败时只看到一句报错 |
| P3 | 首屏认知过载 | 720×800 单页长滚动，多张卡片堆叠 | 常用与高级参数混在一起，1024×768 需滚动 |
| P4 | 主题只有两套配色 | `theme.py` 仅 light/dark；Linux 系统深色默认不跟随 | 看起来像工具，不像有品牌的产品 |
| P5 | 不能录制 | 无录制回放、无宏库 | 重复流程只能手配参数，不能“做一遍再回放” |
| P6 | 停不下来、停不准 | 有启动/停止，无暂停/继续 | 临时中断只能全停，计数归零 |
| P7 | 启动慢 | 源码 5.3–5.7s；onedir 约 4.2s | 双击后等待明显，首启体验差 |
| P8 | 文档与版本漂移 | 标题硬编码 v2.0.2；README 末段仍称 ydotool 未接入 | 用户按旧文档操作，支持成本增加 |
| P9 | 热键冲突无提示 | 支持组合键，但无录制式输入与占用检测 | 设了 Ctrl+Alt+K 不生效，不知道为什么 |

### 1.4 本次要解决的问题

不是“再加十个参数”，而是把产品从“能用”推到“好用、好看、可扩展”：

1. 让新用户在 60 秒内完成第一次成功运行。
2. 让常用操作与高级能力分层，不再堆在一个页面。
3. 让主题成为品牌资产，而不是两套配色。
4. 让重复流程可以录制、保存、复用。
5. 让异常可诊断、版本可追溯、升级可预期。

## 2. 产品定位、目标与成功指标

### 2.1 一句话定位

> 一个能连续跑一整夜也不崩、随时停得下来、在企业内网可审计可批量部署，并且看起来像现代软件的桌面点击值守工具。

### 2.2 三大支柱

| 支柱 | 含义 | 对应能力 |
|---|---|---|
| **可靠** | 长跑稳定、停得下来、异常可恢复 | 防锁屏、failsafe、次数/时长上限、8h 浸泡、日志 |
| **可控** | 企业可部署、可审计、可批量 | 档案、目标窗口校验、CLI、离线安装、单实例、日志落盘 |
| **好看** | 首启顺、界面清楚、主题有辨识度 | 3 步向导、双模式、左侧导航、5 套主题、用户主题包 |

### 2.3 目标与关键结果

| 目标 | 关键结果（KR） |
|---|---|
| O1 让首次上手更快 | KR1 新用户 60s 内完成首次成功运行；KR2 1024×768 主流程无滚动；KR3 上手相关反馈下降 30% |
| O2 让长跑更可信 | KR4 8h 无崩溃/无 Tcl 异常；KR5 内存峰值 ≤60MB、8h 增长 ≤5MB；KR6 停止指令 ≤200ms |
| O3 让自动化够用 | KR7 录制 10 个动作 100% 原序回放；KR8 50 CPS 偏差 <5%；KR9 定时触发误差 <2s |
| O4 让外观有辨识度 | KR10 5 套内置主题 + 用户主题包；KR11 主题切换 <1s；KR12 正文对比度 ≥4.5:1 |
| O5 让交付更专业 | KR13 onedir 冷启动 <3s；KR14 onefile 便携包 ≤40MB；KR15 文档/版本口径 0 处漂移 |

> 不默认埋点。KR3 用 GitHub Issue、用户反馈与可用性测试代理，不做遥测。

### 2.4 非目标（明确不做）

1. 反检测、绕过反作弊、防封号承诺。
2. 进程注入、内存修改、驱动级隐藏。
3. 无提示的后台静默点击。
4. 全功能脚本引擎（AHK/Pulover 级）。
5. 插件市场、第三方插件审核体系。
6. 移动端、Web 控制台、多机集中管理。
7. macOS 原生支持。
8. 图像/OCR 识别点击；图像/颜色等待仅按 FR-18 门禁评估，OCR 不做。

## 3. 用户与场景

### 3.1 用户角色

| 角色 | 特征 | 核心诉求 | 占比预估 |
|---|---|---|---|
| R1 值守运维 | 企业内网、麒麟桌面、长时间保持会话在线 | 稳定、防锁屏、可远程确认、可批量部署 | 45% |
| R2 办公自动化 | 固定业务系统做重复录入/刷新/保存 | 精确取点、次数/时长可控、异常能停 | 30% |
| R3 个人挂机 | 单机、签到/挂机类 | 毫秒级、随机化、快捷键顺手 | 10% |
| R4 自动化进阶 | 测试、批量操作、重复流程 | 录制、宏库、调度、窗口绑定 | 15% |

> R3 仅满足“拟人节奏”的技术能力，不为其规避平台规则背书。

### 3.2 核心场景

**S1 夜间值守（R1）**：下班前设定每 60s 点一次状态区，跑 8h，防锁屏开启，次日查看统计与异常。
**S2 单据批量保存（R2）**：固定系统每 3s 点“保存”，共 200 次；弹窗遮挡或窗口切走时暂停并告警。
**S3 首次使用（R3）**：下载 exe，选“挂机签到”模板，框选区域，按 F6 启动，60s 内完成。
**S4 录制重复流程（R4）**：录制“打开菜单→点击导出→回车→等待 2s”10 个动作，保存为宏，绑定热键，次日回放。
**S5 企业品牌定制（R1）**：IT 下发“海洋蓝”主题包，统一团队视觉；用户也可导入自己的主题。

### 3.3 用户旅程

| 阶段 | 用户动作 | 产品响应 | 关键要求 |
|---|---|---|---|
| 首启 | 双击启动 | 3 步向导（场景→目标→热键）；可跳过 | 60s 内可运行 |
| 配置 | 选模板/取点/设停止条件 | Simple 模式只留 5 个控件；Advanced 展开 | 不认知过载 |
| 启动 | 点开始或按 F6 | 安全确认摘要；倒计时 | 可取消、可记住选择 |
| 运行 | 最小化到托盘 | 运行台/托盘显示状态、剩余、档案 | 暂停/继续可用 |
| 异常 | 弹窗/报错 | 诊断中心给修复步骤 | 不静默失败 |
| 结束 | 自动/手动停止 | 结束摘要 + 历史记录 | 次数/时长/异常可查 |
| 复用 | 想重复流程 | 录制→宏库→绑定热键 | 10 个动作可回放 |
| 升级 | 新版本 | 检查更新/手动下载/离线包 | 校验、可回滚 |

### 3.4 关键体验原则

1. **默认简单，按需高级**：首屏只放能完成一次点击的 5 个控件。
2. **状态先行**：运行/停止/暂停/异常四态一眼可辨，不靠读日志。
3. **错误可执行**：每条错误必须带“下一步做什么”，不能只报错。
4. **主题是数据，不是代码**：主题包只读 JSON，不执行脚本。
5. **不打断点击线程**：UI、主题、托盘、日志都不得阻塞引擎。

## 5. 产品结构（信息架构）

### 5.1 信息架构

```
┌──────────────────────────────────────────────────────────────┐
│ 状态条：● 运行中 · 剩余 00:12 · 已点击 37 次 · 会话保持：开 │
├──────────┬───────────────────────────────────────────────────┤
│ 运行台    │  内容区（随导航切换）                              │
│ 规则      │  · 运行台：状态环 / 今日统计 / 下次计划 / 主操作     │
│ 记录      │  · 规则：点击 / 目标 / 停止条件 / 调度 / 安全        │
│ 设置      │  · 记录：宏库 / 运行历史 / 日志                      │
│          │  · 设置：外观 / 主题 / 语言 / 更新 / 关于             │
├──────────┴───────────────────────────────────────────────────┤
│ 主操作条：[▶ 开始 (F6)] [⏸ 暂停 (F7)] [■ 停止]   倒计时 00:12 │
└──────────────────────────────────────────────────────────────┘
```

**约束**：导航不超过 4 项；主操作条固定底部；暂停按钮在 R2 启用，R1 隐藏；1024×768 与 1280×800 下主流程不出现垂直滚动。

### 5.2 页面职责

| 页面 | 职责 | 首屏内容 |
|---|---|---|
| 运行台 | 看状态、启停、看统计 | 状态环、今日点击、成功率、下次计划、会话保持徽标、开始/暂停/停止 |
| 规则 | 配点击、目标、停止条件、调度、安全 | Simple 模式 5 控件；Advanced 展开 jitter、多点、窗口、调度、安全 |
| 记录 | 管宏、看历史、看日志 | 宏列表、最近 30 次运行、实时日志、导出 |
| 设置 | 管外观、语言、更新、关于 | 主题卡片、字体、语言、检查更新、版本/路径/许可 |

### 5.3 简单 / 高级双模式

| 模式 | 显示内容 | 目标用户 | 切换规则 |
|---|---|---|---|
| Simple | 间隔、目标、次数/时长、防锁屏、开始 | 新用户、一次性任务 | 默认进入；记住上次选择 |
| Advanced | Simple + jitter、多点、按键类型、调度、窗口绑定、安全、日志 | 值守/进阶用户 | 顶部开关切换；不重置配置 |

### 5.4 交互约束

- 主操作条常驻，按钮态与运行状态严格互斥。
- 所有破坏性操作（删除宏、删除主题、导入覆盖）需二次确认。
- 主题切换、页面切换不得阻塞点击线程。
- 任何页面都能在 2 次点击内回到“停止”。

| NFR-15 | 更新安全 | HTTPS + SHA256 + 代码签名；失败回滚；可关闭 | 升级演练 + 故障注入 |

## 8. 关键交互规范

### 8.1 首启向导（FR-01）

| 步骤 | 页面 | 用户动作 | 反馈 |
|---|---|---|---|
| 1 | 选场景 | 选择保持在线/挂机签到/固定按钮连点/自定义 | 右侧展示模板摘要（间隔/目标/停止条件） |
| 2 | 取目标 | 框选区域/点选坐标/跳过 | 半透明遮罩 + 放大镜 + 坐标回填 |
| 3 | 确认热键 | 确认 F6/F8/Esc 或修改 | 展示“按 F6 开始，F8/Esc 随时停止” |
| 完成 | 运行台 | 点“开始”或按 F6 | 60s 内可完成首次成功运行 |

跳过向导：使用“推荐安全”档案，不覆盖已有配置；设置页可再次打开向导。

### 8.2 运行台状态（FR-26；暂停态在 R2 启用）

| 状态 | 颜色 | 文案 | 主按钮 | 附加信息 |
|---|---|---|---|---|
| 已停止 | 中性灰 | 已停止 | 开始 | 上次运行摘要 |
| 运行中 | 绿色 | 运行中 · 剩余 00:12 | 停止 | 今日点击/成功率/下次计划 |
| 已暂停（R2） | 黄色 | 已暂停 · 计数 37 | 继续/停止 | 暂停原因（手动/窗口切走） |
| 异常 | 红色 | 异常 · 输入后端不可用 | 停止/诊断 | 一句原因 + “查看诊断” |

### 8.3 取点（FR-27）

- 全屏变暗 40%，十字线跟随鼠标，右上角放大镜显示 5×5 像素与坐标。
- 拖拽取矩形；单击取中心点；方向键 1px 微调，Shift+方向键 10px。
- 靠近屏幕边缘 8px 自动吸附；支持负坐标与多显示器。
- Esc 取消，原值不变；Enter 确认并回填。
- 取点期间主线程不得阻塞 >100ms。

### 8.4 录制与回放（FR-13）

| 阶段 | 行为 | 反馈 |
|---|---|---|
| 开始录制 | 3s 倒计时，明确提示“只记录点击/按键/延时，不记录轨迹” | 托盘图标变红，状态条“录制中” |
| 录制中 | 记录 click/key/wait；可暂停/继续；Esc 停止 | 步骤计数实时显示 |
| 结束 | 保存为 `macros/<name>.json`，打开预览 | 显示步骤数/时长/文件路径 |
| 回放 | 选择宏、速度 0.5–2x、循环次数 | 倒计时后开始；Esc/F8 随时停止 |
| 异常 | 坐标越界/窗口不匹配/文件损坏 | 行内提示 + 诊断入口 |

说明：`move` 仅记录点击时刻的离散坐标，不记录鼠标连续轨迹；录制器不注入其他进程，全局监听仅在用户主动录制时启用。

### 8.5 主题切换（FR-33～FR-35）

- 设置页展示主题卡片（缩略色块 + 模式 + 作者），点击即预览，确认后应用。
- 切换 <1s；不重启；不中断点击线程；布局不塌陷。
- 非法主题包：字段级错误 + “恢复默认”，不覆盖当前主题。
- 系统模式：手动选择优先；系统变化 5s 内跟随。

### 8.6 诊断中心（FR-03）

| 区块 | 内容 | 操作 |
|---|---|---|
| 环境 | OS/会话/DPI/输入后端/Python 版本 | 复制 |
| 热键 | 已注册键、冲突键、占用进程 | 重新检测 |
| 权限 | 自启、输入模拟、日志目录 | 打开设置 |
| 日志 | 最近 200 行，级别过滤 | 打开日志目录 |
| 诊断包 | 脱敏后的 zip（环境+日志+配置摘要） | 一键复制/保存 |

### 8.7 暂停与按住（FR-06）

- 暂停按钮/F7：点击线程挂起，计数不清零；继续后从下一周期开始。
- 按住运行：按住指定热键时运行，松开 200ms 内停止；适合短时手动控制。
- 急停（Esc/F8/托盘/甩角）优先于暂停与按住。

## 9. 视觉与主题规范

### 9.1 设计原则

- **清楚优先**：状态、主操作、危险操作三者的视觉权重不可混淆。
- **扁平精致**：细分隔线、8px 网格、克制阴影；不追求复杂圆角/动画。
- **主题是数据**：颜色、字体、间距都来自令牌，业务代码零裸色值。
- **可访问**：颜色不是唯一信息载体；对比度、焦点、键盘全流程达标。

### 9.2 主题矩阵

| 主题 | 模式 | bg | surface | text | primary | 适用 |
|---|---|---|---|---|---|---|
| 晨曦 | 浅色 | `#FFFFFF` | `#F6F7F9` | `#16181D` | `#2563EB` | 默认浅色、办公 |
| 深空 | 深色 | `#16181D` | `#1F2229` | `#E8EAED` | `#60A5FA` | 夜间值守 |
| 高对比 | 高对比 | `#000000` | `#0A0A0A` | `#FFFFFF` | `#FFD400` | 低视力/强光 |
| 海洋蓝 | 深色品牌 | `#0F172A` | `#1E293B` | `#E2E8F0` | `#38BDF8` | 品牌主视觉 |
| 暖沙 | 浅色护眼 | `#FBF7EF` | `#F3EBDD` | `#2B2118` | `#B45309` | 长时间阅读 |

> 每套主题必须定义 `on_primary`，高对比主题主按钮用黑字黄底；正文对比度 ≥4.5:1，控件边界 ≥3:1。

### 9.3 设计令牌

| 类别 | 令牌 | 约束 |
|---|---|---|
| 背景 | `bg` / `surface` / `surface_alt` | 三层明度差可辨 |
| 文本 | `text` / `muted` | 正文 ≥4.5:1；辅助 ≥3:1 |
| 主色 | `primary` / `primary_hover` / `primary_pressed` / `on_primary` | 三态色阶协调 |
| 状态 | `success` / `danger` / `warning` | 必须配文案/图标，不单独用颜色 |
| 边界 | `border` / `focus` | 焦点环 2px，对比度 ≥3:1 |
| 字体 | `ui` / `mono` / `scale` | 回退链 + 用户缩放 |
| 间距 | 4/8/12/16/24 | 8px 网格 |
| 字号 | 12/14/16/20/28 | Display 用于倒计时 |
| 控件 | 输入高 32、主按钮 40、圆角 6/8 | 跨平台一致 |

### 9.4 字体与图标

- UI 字体：微软雅黑 → 思源黑体 → Noto Sans CJK SC → 文泉驿微米黑 → DejaVu Sans。
- 等宽：Consolas → JetBrains Mono → DejaVu Sans Mono。
- 图标：16/20/24px 单色线性；禁用 emoji 功能图标；托盘提供浅/深两套 16/32px。
- 图标颜色随 `text`/`muted`；状态图标随 `success`/`danger`/`warning`。

### 9.5 主题包规范

| 字段 | 必填 | 约束 |
|---|---|---|
| `schema` | 是 | 固定 `autoclicker.theme/1` |
| `id` | 是 | 小写字母/数字/连字符，≤32 字符，唯一 |
| `name` | 是 | ≤24 字符，可中文 |
| `mode` | 是 | `light` / `dark` / `high_contrast` |
| `colors` | 是 | 14 个必填令牌，`#RRGGBB` |
| `typography` | 是 | `ui` / `mono` / `scale` |
| `meta` | 否 | `author` / `version` / `description` |

校验：只允许 JSON 数据，不允许脚本、URL、文件路径；非法包拒绝加载并给出字段级错误。用户主题目录：`~/.auto_clicker/themes/`；便携模式 `<exe>/data/themes/`。

### 9.6 可访问性

- 正文对比度 ≥4.5:1；控件边界/焦点 ≥3:1。
- 状态不能只靠红/绿：必须同时有文案/图标。
- 全流程可键盘完成；焦点环 2px；Enter 主操作；Esc 取消。
- 支持“减少动效”；色弱模式避免红绿唯一编码。

## 10. 数据模型与配置

### 10.1 配置文件

**保留现有路径**：`~/.auto_clicker_config_py3.json`。旧 PRD 提出的改名为 `~/.auto_clicker_config.json` **取消**，原因是会破坏现有用户配置且收益低；新增 `schema_version: 3` 做结构升级。便携模式（`portable.flag` 存在）下，配置、日志、宏、主题统一放 `<exe>/data/`。

```json
{

    "theme_pack": "system",

    "language": "zh-CN",
    "window": { "w": 960, "h": 680 }
  },
  "active_profile": "默认",
  "profiles": {
    "默认": {
      "interval": { "value": 60, "unit": "s", "jitter_pct": 0 },
      "click": { "button": "left", "type": "single", "hold_ms": 80, "double_gap_ms": 80 },
      "target": {
        "mode": "center",
        "area": { "x": 0, "y": 0, "w": 1920, "h": 1080 },
        "points": [],
        "window_binding": { "title": "", "process": "", "class": "" }
      },
      "rhythm": { "cps_min": 0, "cps_max": 0, "duty_pct": 50, "hold_to_run": false },
      "limit": { "type": "duration", "count": 0, "duration_min": 480, "on_finish": "notify" },
      "schedule": {
        "enabled": false,
        "windows": [
          { "start": "09:00", "stop_after_min": 0, "weekdays": [1, 2, 3, 4, 5] }
        ]
      },
      "keep_awake": true,
      "safety": { "confirm_on_start": true, "corner_stop": true, "esc_stop": true },
      "hotkey": { "toggle": "F6", "pause": "F7", "stop": "F8" }
    }

  "macros": { "dir": "macros", "recent": [] },
  "logging": { "level": "info", "ring_lines": 500, "file_enabled": true, "retain_days": 7 },
  "diagnostics": { "last_bundle": "" }

```

### 10.2 字段约束

| 字段 | 类型 | 约束 | 默认 |
|---|---|---|---|
| `schema_version` | int | 必须为 3；旧版自动迁移 | 3 |
| `ui.theme_pack` | string | `system` / `light` / `dark` / `high_contrast` / `ocean` / `sand` / 用户主题 id | `system` |
| `ui.accent` | string | `#RRGGBB` 或空；空表示使用主题主色；非空需对比度校验 | 空 |
| `ui.mode` | enum | `simple` / `advanced` | `simple` |
| `interval` | object | 换算后 1ms–24h | `60s` |
| `interval.value` | number | >0；与 unit 换算后在 1ms–24h | 60 |
| `interval.unit` | enum | `ms` / `s` / `min` / `h` | `s` |
| `rhythm.cps_min/max` | int | 0 或 1–200；min ≤ max；0 表示关闭 | 0 |
| `rhythm.duty_pct` | int | 10–90 | 50 |
| `schedule.windows` | array | 每项 start HH:MM、stop_after_min ≥0、weekdays 1–7 | 1 项 |
| `target.window_binding` | object | 标题/进程/类名任一可空；空表示不绑定 | 空 |
| `macros.dir` | string | 相对 `~/.auto_clicker/` 或绝对路径；禁止 `..` | `macros` |
| `logging.retain_days` | int | 1–30 | 7 |

### 10.3 宏文件

路径：`~/.auto_clicker/macros/<name>.json`；便携模式 `<exe>/data/macros/`。

```json
{
  "schema": "autoclicker.macro/1",
  "name": "每日签到",
  "speed": 1.0,
  "loop": 1,
  "steps": [
    { "t": "move", "x": 120, "y": 340, "delay_ms": 300 },
    { "t": "click", "button": "left", "count": 2, "interval_ms": 80 },
    { "t": "key", "key": "ENTER", "delay_ms": 200 },
    { "t": "wait", "ms": 1500 }
  ]
}
```

约束：`speed` 0.5–2.0；`loop` 1–999；`delay_ms` 为该步执行后的延时；`wait` 为显式等待；步骤仅 `move/click/key/wait`；不记录轨迹；不支持任意代码；播放前校验坐标在虚拟桌面内；Esc/F8 可中断。

### 10.4 迁移规则

| 源 | 目标 | 规则 |
|---|---|---|
| v1 `interval_seconds` | v3 `interval{value,unit:"s"}` | 直接映射 |
| v1 `click_mode` | v3 `target.mode` | 同名字符串映射 |
| v1 `click_area{x,y,width,height}` | v3 `target.area{x,y,w,h}` | 字段重命名 |
| v2 `schedule.start_at/stop_after_min/weekdays` | v3 `schedule.windows[0]` | 单窗口转数组 |
| v2 `theme_mode` | v3 `ui.theme_pack` | light/dark/system 映射 |
| 未知旧键 | `_legacy` | 保留不丢弃 |
| 损坏 JSON | 备份 `config.bad.<timestamp>.json` | 恢复默认并提示 |

迁移必须：幂等、可回滚、不丢字段；迁移前自动备份；失败时保留原文件可用。

**依赖关系**：
- R2 依赖 R1 的 UI 壳、主题令牌、诊断中心。
- 录制依赖稳定的输入钩子与引擎分层；不得把 Tk 调用带入录制线程。
- 自动更新依赖代码签名与 NSIS 静默安装；未签名前只做手动下载。
- 多语言依赖 UI 文案冻结；放在 R3，避免 R1/R2 反复改文案。
- 图像/颜色等待依赖变更评审；MCP 依赖安全评审。

**排期建议**：1 人全职按 R1→R2→R3 顺序推进；2 人并行时，1 人负责 UI/主题，1 人负责引擎/录制，R3 另立里程碑。

## 14. 风险与依赖

| 风险 | 影响 | 应对 |
|---|---|---|
| UI 重构回归 | 高 | R1 冻结功能改动；四档 DPI 截图回归；主流程自动化冒烟 |
| 录制钩子触发杀软误报 | 高 | 代码签名；首次使用说明；不做隐藏/注入；提供白名单指引 |
| 主题包恶意内容 | 中 | 仅 JSON；schema 校验；禁止 URL/路径/脚本；加载前预览 |
| 配置迁移丢字段 | 高 | 迁移前备份；幂等；`_legacy` 保留未知键；失败回滚 |
| 启动优化不达标 | 中 | onedir 优先；延迟导入；启动打点；必要时接受 3.5s 并记录 |
| Linux 主题检测碎片化 | 中 | gsettings/KDE 双路径；失败回退手动 |
| 多语言波及全部 UI | 中 | UI 冻结后做；先抽离文案字典 |
| 自动更新被劫持 | 高 | HTTPS + SHA256 + 签名；失败回滚；可关闭 |
| Scope creep 到脚本引擎 | 高 | 录制四类步骤硬约束；新步骤类型需评审 |
| 1 人排期过长 | 中 | P0 先交付；R2 可拆给第二人；R3 单独立项 |

**依赖**：
- 代码：`auto_clicker_py3.py`、`auto_clicker_layers/{config,engine,theme,platform_io,ui}.py`。
- 平台：`pyautogui`、`keyboard`、`pywin32`（Windows）、`pyperclip`；Linux `python-xlib`、`pystray`、`Pillow`；Wayland `ydotool`/`ydotoold`。
- 打包：PyInstaller、NSIS；发布：GitHub Release。
- 测试：现有 `tests/`；新增 UI 冒烟、主题对比度、录制回放、迁移测试。
