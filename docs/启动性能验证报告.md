# 启动性能验证报告（T05277 / NFR-05）

- 验证日期：2026-11-16
- 环境：Windows 10 Pro 19045，Python 3.14.3，DPI 200%，用户真实桌面会话
- 代码：`D:\code\otherProjects\AutoClicker\auto_clicker_py3.py`
- 结论：**NFR-05「冷启动 3s 内」未达成**；已完成两轮可落地的启动优化，源码启动由 14.1s 降至约 5.4s，onedir 打包产物约 4.2s。任务 T05277 只标 `done`，不标 `verified`；继续优化由既有任务 T05267（REQ-005 启动性能优化）承接。

## 1. 判定口径与测量方法

- NFR-05：应用从进程启动到主窗口可交互 ≤ 3s。
- 源码探针 `C:\pyfix_tmp\ac_startup_probe.py`：记录脚本启动 → 导入 `auto_clicker_py3` → 创建 `tk.Tk()` → `AutoClicker(root)` 初始化 → `root.update()` 的耗时，并拆分 `import_ms` / `init_ms`。
- 打包产物：`Start-Process` 启动 exe，50ms 轮询 `Process.MainWindowHandle`，首次非 0 即记为窗口出现；测后关闭该测试进程。使用 `AUTOCLICKER_MUTEX_NAME` / `AUTOCLICKER_WINDOW_TITLE` 隔离单实例互斥，避免影响用户正在运行的 AutoClicker。
- 三次取样，报告同时给出冷缓存首次与热缓存后续值，避免只取最好的一次。

## 2. 优化前基线

| 轮次 | 源码 startup_ms | import_ms | init_ms |
|---|---:|---:|---:|
| 1（冷） | 14140.3 | 约 9500 | 约 4600 |
| 2 | 10584.8 | 约 7400 | 约 3100 |
| 3 | 11307.5 | 约 8200 | 约 3100 |

`-X importtime` 最大单点：`pyautogui` 链（mouseinfo / pyscreeze / pygetwindow）约 **8.44s**；项目在 Windows 上实际使用 ctypes/Win32 原生点击，pyautogui 只是无原生后端时的降级路径。

## 3. 第一轮优化：pyautogui 懒加载

- 顶部 `import pyautogui` 改为 `_get_pyautogui()` 首次降级调用时才导入；`linux_move_mouse`、`linux_get_cursor_pos`、`get_cursor_pos`、`move_mouse`、`_pyautogui_click` 等调用点改为惰性获取，避免模块导入期拉起整条截图/窗口依赖链。
- 结果：源码启动 9594.7 / 5991.0 / 9721.3ms（import 2.9–5.3s、init 3.1–4.6s）。

## 4. 第二轮优化：keyboard 与托盘延后到窗口显示后

- `keyboard` 顶部导入（约 1.3s 全局钩子初始化）改为 `_get_keyboard()` 懒加载；`_register_hotkeys()` 首次使用时加载。
- `setup_hotkeys()` 与 `setup_tray_icon()` 从 `AutoClicker.__init__` 同步调用改为 `root.after(50/120, ...)`，主窗口先显示，再在主线程空闲回调中注册热键、创建托盘。
- 实测真实运行日志确认延迟初始化成功：窗口出现后输出「快捷键已注册：启动=f6，紧急停止=f8，Esc」「系统托盘图标创建成功」，窗口标题与探针标题可正常读取。
- 结果（正常探针三连测）：

| 轮次 | startup_ms | import_ms | init_ms |
|---|---:|---:|---:|
| 1 | 5316.1 | 1696.1 | 3620.0 |
| 2 | 5719.8 | 3062.4 | 2657.3 |
| 3 | 5430.1 | 2236.1 | 3194.0 |

中位数约 **5.43s**；相比基线下降约 52%–62%，但仍高于 3s。

### 4.1 热点剖面

`cProfile`（`C:\pyfix_tmp\ac_startup3.prof`）显示剩余耗时集中在：

- 模块导入约 1.77s（tkinter、win32gui/win32api、PIL、logging 等）；
- `Tk()` 创建及 Tcl/Tk 初始化约 0.86s；
- `AutoClicker.__init__` 约 1.14s，其中 `setup_ui()` 约 0.91s（约 600 次 Tk `call`）；
- 解释器自身启动与 site 初始化约 0.8–1.0s。

在单线程 Tk 初始化模型下，仅靠继续删减 import 无法把源码启动压到 3s 内。

## 5. 打包策略对比：onefile vs onedir

现有发布配置 `scripts/config.build.json` 使用 `--onefile --windowed`；onefile 每次启动要把 33MB 归档解压到临时目录，启动开销高于 onedir。为验证策略，另建 onedir 包：

- 产物：`D:\code\otherProjects\AutoClicker\release\dist_onedir\AutoClickerOnedir\AutoClickerOnedir.exe`
- 构建：PyInstaller 6.20.0，`--onedir --windowed`，包含 icons、pyautogui/keyboard/PIL/win32 等 hidden imports
- 隔离变量启动实测：

| 轮次 | 窗口出现 startup_ms |
|---|---:|
| 1 | 3969.7 |
| 2 | 4675.1 |
| 3 | 4181.1 |

中位数约 **4.18s**，比当前源码启动快约 1.2–1.5s，但仍未达到 3s。onedir 目录体积明显大于 onefile 单文件，且现有 `scripts/publish_package.ps1` 只按单 exe 打包，切换到 onedir 需要同步改造发布链路（属于 T05250 打包与升级任务范围）。

## 6. 结论与后续

1. NFR-05 3s 在当前 Windows 10 + Python 3.14 + Tk 单进程初始化条件下未达成；不能把 T05277 标为 `verified`。
2. 两轮优化已消除两个最大非必要开销（pyautogui 8.44s 导入链、keyboard 1.3s 钩子初始化），并把 onedir 作为更快的打包候选。
3. 进一步压到 3s 需要改变启动架构，而不是继续微调 import：
   - 先显示轻量启动窗口/骨架，再在后台线程或 `after` 分帧构建完整 UI；
   - 或改用 Nuitka 等编译型打包，减少 Python 解释器与 frozen import 开销；
   - 发布侧同时评估 onedir/安装器方案与 onefile 的兼容取舍（T05250）。
4. 后续优化已由既有任务 **T05267（REQ-005 启动性能优化）** 承接，本报告不重复建单。
