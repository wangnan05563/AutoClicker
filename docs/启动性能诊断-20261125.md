# 启动性能诊断（T06328）

- 日期：2026-11-25
- 环境：Windows 10 企业版 19045，Python 3.14.3，PyInstaller 6.20.0，NVMe SSD
- 结论：**AC-16 仍未达标**。当前源码首屏 2.73s，但新建 onedir 产物稳定态中位数 8.105s；裁剪 Tcl 数据后可降到 6.534s（约 19.4%），仍高于 3s。005 原始产物缺失，23.95s 无法同文件复核。

## 1. 实测数据

| 对象 | 文件数 | 体积 | 5 次样本（秒） | 中位数 |

| 已安装 004 产物 | 1028 | 39.9 MB | 57.910 / 7.826 / 5.199 / 3.430 / 8.913 | 7.826 |
| 新建 onedir | 1029 | 44.6 MB | 13.163 / 6.215 / 10.498 / 5.441 / 8.105 | 8.105 |

- 计时口径：从 `CreateProcess` 到进程拥有可见、有标题的主窗口；不是日志 `ROOT_READY`，也不是只创建 Tk root。
- 每轮使用独立 `USERPROFILE`、`HOME` 与 `AUTOCLICKER_MUTEX_NAME`，避免读写用户配置和单实例互斥干扰。
- onefile 多个样本只出现标题为 `Error` 的窗口或 60s 无主窗口，不能作为可用产物。
- 首启新 exe 有 13.2s、17.9s、57.9s 的离群值；稳定态仍为 6.2–8.1s，符合 Defender 对新文件的扫描特征。

## 2. 裁剪实验

在构建完成后删除以下纯 Tcl/Tk 运行时数据：

- `_internal/_tcl_data/tzdata`（时区数据，应用未使用 Tcl `clock`）
- `_internal/_tcl_data/msgs`（Tcl 本地化消息）
- `_internal/_tk_data/msgs`（Tk 本地化消息）

文件数从 1029 降到 275，稳定态中位数从 8.105s 降到 6.534s。产物仍能启动并显示主窗口，但没有替代 `msgs` 后的完整本地化/对话框回归，因此该裁剪目前只作为候选优化，未写入正式构建流程。

## 3. 根因判断

1. **源码侧不是主因**：T06166 已测得源码 `ROOT_READY=0.84s`、`INIT=2.55s`、`TOTAL=2.73s`，`setup_ui=0.67s`；本次诊断没有发现新的 Python 初始化回退。
2. **主要增量在打包运行时**：同机 onedir 稳定态比源码多约 3.5–5.4s，且与文件数量、首次扫描强相关。
3. **Defender 首次扫描成本高**：新 exe 首启 13–58s；稳定后仍要 6s 左右。未签名产物无法靠应用代码消除该成本。
4. **onefile 不可行**：体积减到 21.6 MB，但启动/解压路径在该机出现 Error 或 60s 无主窗口，不能作为达标方案。
5. **UI 延迟初始化已做过**：日志、图标、热键、托盘已在 T05267 后移；继续在 Python 侧挤 3s 的空间有限。

## 4. 结论与后续建议

- **AC-16 结论：FAIL**。不能把 6.534s 或单次 3.43s 写成通过。
- 若继续追 3s，优先做以下三项，而不是继续微调 Tk：
  1. 代码签名 + 安装器/企业环境 Defender 信任链，消除首次扫描离群值；
  2. 将 Tcl 数据裁剪纳入构建后处理，并补 `msgs` 缺失的本地化回归；预计只能到 6.5s 量级；
  3. 评估原生启动器/早期骨架窗口或 Nuitka 方案，但需单独任务验证，不得直接把 onefile 当作达标方案。
- 005 的 `release/startup-bench-20261124-001.json`、`build-005.log` 与 dist 已缺失，无法对 23.95s 的原始中位数做同文件复核；本报告只对当前可构建产物负责。

## 5. 复现

- 构建：`scripts/build_exe.py` 同等 PyInstaller 参数，输出到隔离目录。
- 测量：`startup_installed_probe.py`，参数为目标 exe 路径；每次启动独立 profile，轮询可见主窗口。
- 数据：`docs/startup-bench-20261125.json`。
