## 0. 结论

**审查时结论：需修复后复审，不建议当时 HEAD 直接通过验收门。当前修复状态见上节。**

本轮改动的模块分层总体比旧版清楚：主题、历史、宏、多点位、配置已有独立层，纯逻辑测试可读性较好；历史/宏/多点位采用临时文件 + `os.replace` 的原子写也值得保留。

但存在 6 个必须先处理的问题：

1. **AC-05 记录页不是“通过”，而是严重横向裁剪**：默认 1000/921 宽度下，宏录制、回放按钮实际落在宏卡片之外，用户看不到也点不到。
2. **AC-10 的 clam 固定会被 ttkbootstrap 绕过**：只要开发/源码环境安装了可选的 `ttkbootstrap`，运行时仍会调用 `theme_use`，重新引入 13–16 秒级切换。
3. **停止后快速重启存在旧点击线程与新增点击线程并发的风险**：长按住点击时 `join(timeout=2)` 可能超时，旧线程仍会读取共享的 `is_running`。
4. **按住时长没有上限且不可取消**：最长可配置任意毫秒，停止/退出只等待 1.5–2 秒，可能在鼠标按键仍按下时结束进程；双击路径还会把失败当成功。
5. **真实鼠标录制使用 `GetKeyState` 而非 `GetAsyncKeyState`**：20ms 轮询线程没有消息队列，可能长期读不到全局按键状态，宏录制/AC-18 实际不可靠。
6. **“推荐安全”首启模板会真实点击**：`mouse_move_only=False`，跳导向导后目标通常是当前光标/屏幕中心，存在首次使用误点击风险。

## 1. 高优先级问题

### H1. AC-05 记录页横向裁剪，默认窗口下宏控件不可见

**位置**：`auto_clicker_py3.py:4307-4341`、`4349-4375`、`4377-4399`

**实测证据（本轮新增探针）**：

- 为模拟 1024×768 屏幕的现有窗口公式，窗口设为 `921×691`；记录页 canvas 视口 `750×552`。
- `records_top` 实际 `722`，请求宽 `1217`。
- `history_card` 实际/请求宽均 `507`。
- `macro_card` 实际宽 `205`，请求宽 `700`。
- `开始录制` 按钮起点 `x=210`、终点 `282`；`停止回放` 起点 `x=479`、终点 `551`。宏卡宽度只有 `205`，右侧控件全部被父容器裁剪。
- 1000×648 探针此前也显示：canvas `829×509`，`records_top` 请求 `1203`，`history_card` 请求 `507`，`macro_card` 实际 `284`/请求 `686`。即宽度问题不是个别 DPI 下的偶发。

**根因**：

1. `records_top.grid_columnconfigure(0, minsize=330)` 只是最小宽度，不是最大宽度。`history_head` 的摘要 Label 没有 `wraplength`，又与“导出 CSV / 刷新”同一行，`history_card` 的请求宽被撑到 507；Grid 会优先满足子控件请求宽，历史列实际占 507。
2. 宏卡的说明文字固定 `wraplength=560`，录制行/回放行把输入框和 5–6 个按钮全部 `pack(side=LEFT)` 在同一行，整卡请求宽约 700。
3. 页面 canvas 的 `bbox` 被裁剪到视口宽度，因此 `horizontal_overflow` 判定为 false。**这是验收探针的假阴性**，不是布局合格。
4. 两列在默认宽度下根本放不下：需要约 `507 + 700 + 10 = 1217px` 内容宽，而默认内容宽只有 750–829px。仅把 `minsize` 调小或加横向滚动不能解决可读性和可操作性。

**影响**：

- Advanced 用户进入记录页后，宏录制、停止、回放、诊断等控件不可见，功能实际不可用。
- 若只修 `history_card` 的请求宽，宏卡仍需要约 700px；在默认窗口下仍会被裁到 205–284px。
- 现有“纵向四页免滚动”结论仍然成立，但它不能证明横向可用；AC-05 必须同时验收宽和高。

**修复建议**：

1. 默认布局改为上下堆叠或“运行历史 / 录制回放”分页（`ttk.Notebook`）。两列仅作为宽屏增强，断点应按**内容宽 ≥1250px**判断，不能按窗口宽 1000 判断。
2. 历史摘要改为可换行 Label（窄屏 `wraplength≈220`），按钮移到第二行；不要用同一个 `history_head` 横排。
3. 宏录制行拆成两行：第一行名称 + 开始/暂停/停止，第二行宏目录 + 诊断；回放行拆成“宏文件 + 刷新”和“回放/暂停/停止”两行。
4. 说明文字的 `wraplength` 改为在 `<Configure>` 时按卡片实际宽度动态设置，不要固定 560。
5. 将 `history_holder`、`macro_holder` 保存为实例属性，绑定防抖 `<Configure>` 做响应式重排。
6. 验收探针改为断言 `records_top.winfo_reqwidth() <= canvas.winfo_width()`，并逐个断言按钮右边界不超出宏卡；不能只看 `bbox`。

参考实现（布局骨架）：

```python
RECORDS_TWO_COL_MIN = 1250  # 内容宽，不是窗口宽

def _layout_records_page(self, _event=None):
    width = self.records_top.winfo_width()
    if width >= RECORDS_TWO_COL_MIN:
        self.history_holder.grid(row=0, column=0, sticky='nsew', padx=(0, 10))
        self.macro_holder.grid(row=0, column=1, sticky='nsew')
        self.records_top.grid_columnconfigure(0, weight=0)
        self.records_top.grid_columnconfigure(1, weight=1)
    else:
        self.history_holder.grid(row=0, column=0, sticky='ew')
        self.macro_holder.grid(row=1, column=0, sticky='ew', pady=(10, 0))
        self.records_top.grid_columnconfigure(0, weight=1)
        self.records_top.grid_columnconfigure(1, weight=0)

# 构造时
self.history_holder = ttk.Frame(self.records_top)
self.macro_holder = ttk.Frame(self.records_top)
self.records_top.bind('<Configure>', self._debounce_records_layout)
```

验收断言示例：

```python

assert app.records_top.winfo_reqwidth() <= canvas_w
```

### H2. ttkbootstrap 会让 clam 固定失效，AC-10 条件性回归

**位置**：`auto_clicker_py3.py:727-770`、`860-869`、`1673-1681`

**问题链路**：

1. `_init_theme()` 先调用 `_pin_ttk_base_theme()`，把当前 ttk 主题设为 `clam`，并缓存 `_ttk_base_theme='clam'`。
2. 随后若 `import ttkbootstrap` 成功，`ttkb.Style(theme='cosmo')` 会把当前主题改成 `cosmo`。
3. `_ttk_base_theme` 仍为 `'clam'`；下次 `_pin_ttk_base_theme()` 因缓存非空直接 `return`，不会纠正实际主题。
4. 每次 `_apply_theme()` 都调用 `_apply_ttkbootstrap_theme()`；其中 `self._ttkb_style.theme_use('darkly'/'cosmo')` 在可见窗口执行，重新触发 ttk 原生元素重建。

**影响**：只要源码/开发环境安装了可选的 `ttkbootstrap`（`requirements` 中未固定禁止），AC-10 的“运行时不再 theme_use”前提就不成立，主题切换可能回到 13–16 秒级；同时 clam 的手工颜色覆盖与 ttkbootstrap 主题样式会互相覆盖。

**触发场景**：开发机或用户环境 `pip install ttkbootstrap` 后启动，切换任一主题。

**修复建议**：

- 不再实例化 `ttkb.Style`，将 `_ttkb_style` 固定为 `None`，或彻底移除 `_apply_ttkbootstrap_theme` 调用；应用已经有一套手工语义色，没必要保留第二套主题源。
- `_pin_ttk_base_theme()` 改为检查实际 `style.theme_use()`，而不是只看缓存：

```python
def _pin_ttk_base_theme(self):
    style = ttk.Style(self.root)
    if self._ttk_base_theme and style.theme_use() == self._ttk_base_theme:
        return
    if 'clam' not in style.theme_names():
        raise RuntimeError('clam 主题不可用')
    style.theme_use('clam')
    self._ttk_base_theme = 'clam'
```

- 增加一个假装安装了 `ttkbootstrap` 的条件单测：断言 `_apply_theme()` 不调用 `theme_use`，且 `style.theme_use() == 'clam'`。
- 若产品确实需要 ttkbootstrap 外观，应把它限定在窗口映射前，且运行时切换只能改颜色，不能改主题名；当前代码不满足这个约束。

### H3. 停止后快速重启可能产生旧/新点击线程并发

**位置**：`auto_clicker_py3.py:5744-5760`（`stop_clicking` 的 `join(timeout=2)`）、`5239-5249`（单次点击按住）、`5275-5284`（达到上限时在点击线程内停止）

**问题**：

- `stop_clicking()` 先把 `is_running=False`，然后 `join(timeout=2)`。但单次点击的 `hold_ms` 可达 5000ms（且当前没有上限），线程可能仍在 `click_mouse()` 的 `time.sleep(hold_ms/1000)` 中。
- 2 秒后 `stop_clicking` 返回，UI 显示已停止；用户此时再次启动，`start_clicking()` 把共享的 `is_running` 置为 `True`，并创建新线程。
- 旧线程从 sleep 返回后继续执行循环，看到的是新的 `is_running=True`，于是也会继续点击。此时旧线程和新线程同时在跑，点击计数、成功/失败统计混在一起。
- 即使不重启，旧线程在 join 超时后仍会继续完成当前点击并递增 `click_count`，而停止摘要已经按旧计数生成，导致结束摘要少计。

**触发**：按住时长 >2 秒（例如 3000–5000ms），点击运行中停止，2 秒内再次点击“开始”。

**修复建议**：

- 立即防御：`start_clicking()` 开头检查 `self.click_thread and self.click_thread.is_alive()`；仍存活则提示“上一轮点击线程尚未退出，请稍候”，不启动新线程。停止后按钮也应保持禁用，直到线程真正结束。
- 正确修复：为每轮运行分配 `run_id`/`threading.Event`，线程只认自己的 token，所有循环条件使用 `_run_active(run_id)`，不要依赖共享布尔值。
- `stop_clicking` 的 `join` 上界必须覆盖最大单次点击耗时；若按住时长上限设为 5000ms，至少等待 5 秒以上，或使用可取消的按住（见 H4）。

参考实现：

```python
def start_clicking(self, ...):
    if self.click_thread and self.click_thread.is_alive():
        self.show_operation_message(
            "上一轮点击线程尚未完全停止，请稍后重试", level='warning')
        return
    self._run_id += 1
    run_id = self._run_id
    self.click_thread = threading.Thread(
        target=self.run_clicking, args=(run_id,), daemon=True)

def run_clicking(self, run_id):
    while self.is_running and run_id == self._run_id:
        if not self._run_active(run_id):
            break
        # ... 原有单次点击逻辑
```

### H4. 按住时长无上限、点击不可取消，停止/退出可能留下鼠标按键按下

**位置**：`auto_clicker_layers/engine.py:233-239`、`auto_clicker_py3.py:4165-4166`、`5495`、`auto_clicker_layers/platform_io.py:268-300`、`auto_clicker_py3.py:7389-7394`

**问题**：

1. `validate_hold_ms()` 只校验非负，不设上限；UI 是普通 `Entry`，可输入任意整数。`self.hold_ms` 最终直接传给 `click_mouse`。
2. `_windows_click_button()` 在按下后 `time.sleep(hold_ms/1000)`，没有取消事件；`stop_clicking()` 只等 2 秒，`_shutdown_runtime()` 只等 1.5 秒。退出时如果点击线程还在 sleep，进程结束前可能没有发 `MOUSEEVENTF_*UP`，系统层面鼠标按键可能保持按下。
3. `windows_click()` 的双击分支无条件 `return True`，即使两次 `_windows_click_button` 都返回 `False`；`_click_once_at` 会把失败计为成功并跳过 pyautogui 兜底。
4. 按住时长大于间隔时，实际点击周期被 hold 拉长，但启动确认仍显示原 interval，参数互斥校验缺失。

**触发**：用户输入 `hold_ms=5000` 或更大；运行中按停止/紧急停止；或长按住期间关闭程序。双击模式下输入设备拒绝 `SetCursorPos`/`mouse_event` 时也会误报成功。

**修复建议**：

- 增加 `MAX_HOLD_MS = 5000`（与 `duty_hold_ms` 的上限一致），并在 `validate_hold_ms` 拒绝超限；同时校验 `hold_ms <= interval_seconds * 1000`（间隔模式）。
- 将点击按住改为可取消的分片等待，并在 `finally` 中始终发送 UP：

```python
def _windows_click_button(x, y, button, hold_ms, cancel=None):
    ...
    try:
        ctypes.windll.user32.mouse_event(down, 0, 0, 0, 0)
        deadline = time.monotonic() + hold_ms / 1000.0
        while time.monotonic() < deadline:
            if cancel is not None and cancel.is_set():
                break
            time.sleep(min(0.01, deadline - time.monotonic()))
    finally:
        ctypes.windll.user32.mouse_event(up, 0, 0, 0, 0)
```

- 增加 `release_mouse_buttons()`，在 `stop_clicking`、紧急停止、`_shutdown_runtime` 和 `atexit` 中调用，作为最后一道保险。
- 双击分支改为 `ok1 = ...; ok2 = ...; return ok1 and ok2`，失败时允许 `_click_once_at` 走 pyautogui 兜底。

### H5. 宏录制的 Windows 鼠标检测用错 API

**位置**：`auto_clicker_layers/input_capture.py:99-110`、`137-164`

**问题**：

- `_button_down()` 使用 `win32api.GetKeyState(vk)`。该 API 反映调用线程消息队列中的按键状态；录制轮询线程没有消息循环，后台 20ms 轮询可能一直读不到全局鼠标按下。
- 即使能读到，20ms 轮询也会漏掉极快点击；`on_event` 固定写入 `hold_ms=0`，用户长按/拖拽时长没有被记录。
- `start()` 不清空 `error`/`mouse_error`/`_buttons`/`_pressed`；一次键盘监听失败后，即使下次成功也可能继续返回 `False`，或把上次按住状态带入新录制。

**影响**：真实鼠标点击录制可能完全录不到，AC-18 回放验证随之失效；目前没有真实鼠标 E2E 测试，纯逻辑测试无法发现。

**修复建议**：

- Windows 改用 `GetAsyncKeyState`：

```python
return bool(ctypes.windll.user32.GetAsyncKeyState(vk) & 0x8000)
```

- 更稳妥的是使用 `WH_MOUSE_LL` 低级鼠标钩子，在按钮 down/up 事件中记录坐标和时间，避免轮询漏采；保留轮询作为无权限时的降级。
- `start()` 重置 `self.error`、`self.mouse_error`、`self._buttons`、`self._pressed`；`stop()` 同样清空。
- 按 down 时间到 up 时间计算 `hold_ms`，而不是固定 0。
- 增加“真实鼠标点击一次后宏里出现一步 click”的 E2E 测试，至少在 Windows CI 上跑。

### H6. 首启“推荐安全”模板实际执行真实点击

**位置**：`auto_clicker_layers/onboarding.py:87-104`、`162-203`；`auto_clicker_py3.py:2952-2976`

**问题**：

- `SAFE_TEMPLATE['patch']['mouse_move_only'] = False`，描述只写“10 秒一次、3 秒倒计时、位移急停”，没有明确“会真实点击”。
- 跳过向导时 `_finish_onboarding(..., skipped=True)` 调用 `safe_config()`，把该模板写入当前配置，并把名为“推荐安全”的 Profile 保存下来；目标 `click_area` 取当前光标/屏幕中心。首次用户很可能在 AutoClicker 窗口上或桌面中心触发真实点击。
- 启动确认中的 `target_label` 只在“只移动”时追加文案，未在真实点击时显式警示；用户可能只看到“点 (x,y)”就点了开始。

**影响**：首次使用者在不了解目标的情况下产生真实点击，可能误触桌面、其他应用或 AutoClicker 自身；这是产品安全边界问题，不是普通体验问题。

**修复建议**：

- 将 `SAFE_TEMPLATE` 改为 `mouse_move_only=True`，同步描述、Profile 名称和摘要文案，例如“每 10 秒轻微移动鼠标，不点击；适合第一次试用”。
- 若确实要提供“安全点击”模板，必须要求用户在向导第 2 步显式选择目标区域，并在启动确认中加粗“将真实点击”二次确认；不能默认使用当前光标。
- 增加测试：`assert SAFE_TEMPLATE['patch']['mouse_move_only'] is True`；并断言跳过向导后 `config['mouse_move_only']` 为真。

## 4. 与周边模块的一致性/回归风险

1. **主题层**：`_pin_ttk_base_theme` 的缓存与实际 `ttk.Style.theme_use()` 脱节；`ttkbootstrap` 是可选依赖，但代码把它当默认路径调用。主题、按钮、托盘图标的刷新链路在无 ttkbootstrap 时成立，有条件时不成立。
2. **输入层**：自动点击、宏录制、宏回放共用 `click_mouse`，但三处的停止语义不一致：自动点击 join 2s、退出 join 1.5s、宏回放 join 1.5s；都没有取消按住和统一释放鼠标。按住时长上限只在 `duty_hold_ms` 里有 5000ms 限制，用户可配的 `hold_ms` 没有。
3. **报告层**：新增 min/h 单位只改了部分 UI，`run_report` 仍按秒/毫秒硬编码；启动确认与结束摘要可能给出错误单位。
4. **配置/宏/历史层**：历史/宏/多点位已经用原子写，配置层没有；配置中的 `macro_hotkeys` 类型未归一化，一个坏字段会让全部全局热键注册失败。
5. **首启**：`safe_config`/`SAFE_TEMPLATE`/`custom` 三个入口的语义不一致：名字说“安全”但真实点击，名字说“自定义保留”但重置参数。这是典型的跨模块文案与行为回归。
6. **验收口径**：AC-05 只看 `bbox` 高度/`horizontal_overflow`，没有看子控件请求宽；AC-10 只在没有 ttkbootstrap 的环境测；AC-01 的 60s 受主机 GUI 基线影响。当前证据不能支持“全部通过”。
